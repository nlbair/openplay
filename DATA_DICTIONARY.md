# openplay data dictionary

Release data-v0.1.0. Files are Parquet (zstd) unless noted. Read them with DuckDB, PyArrow, pandas, polars, or R arrow.
Generated by code/scripts/final/build_dictionary.py from the real files. Filled is the share of rows that are not blank.

## events

One row per event (pass, shot, tackle, and so on). One file per competition-season: events_<comp>_<season>.parquet. Coordinates run 0 to 100 on both axes and every team attacks toward x = 100. Columns starting with q_ are the provider's qualifiers; see qualifier_dictionary.csv for how each is stored. Different files can have different q_ columns.

579,473 rows in this example file (events_eng_2425.parquet), 149 columns.

| column | type | filled | description |
|---|---|---|---|
| comp | category | 100% | Competition code, see the competitions table |
| season | category | 100% | Season code: club seasons like 2425 for 2024/25, tournaments by year like 2022 |
| match_id | int32 | 100% | Match ID (same as the source match page ID) |
| event_id | int64 | 100% | Global event ID from the source (64-bit). A few OffsideGiven events share an ID with an unrelated event, so use event_id_sub and row order too |
| event_id_sub | int8 | 100% | 0 for most events; 1 for companion events whose source ID ends in .1 (an OffsideGiven paired with its OffsidePass) |
| team_event_id | int32 | 100% | The source's per-team event number. related_event_id on another event of the same team points to this |
| minute | int16 | 100% | Match minute as shown on the clock (stoppage time counts on, for example 45 and 46 in first-half added time) |
| second | int16 | 100% | Second within the minute |
| expanded_minute | int16 | 100% | Minute counted continuously through stoppage time, so it never repeats |
| period | category | 100% | FirstHalf, SecondHalf, FirstPeriodOfExtraTime, SecondPeriodOfExtraTime, PenaltyShootout, PreMatch or PostGame |
| team_id | int32 | 100% | Team ID |
| team | category | 100% | Team name |
| player_id | int32 | 99% | Player ID |
| player | string | 99% | Player name |
| type | category | 100% | Event type, for example Pass, Goal, SavedShot, MissedShots, Tackle, Interception |
| outcome | category | 100% | Successful or Unsuccessful |
| x | float32 | 100% | Start x, 0 (own goal line) to 100 (opponent goal line) |
| y | float32 | 100% | Start y, 0 (right touchline from the attacking team's view) to 100 |
| end_x | float32 | 67% | End x for passes and carries |
| end_y | float32 | 67% | End y for passes and carries |
| is_shot | bool | 100% | True for shots (Goal, SavedShot, MissedShots, ShotOnPost) |
| is_goal | bool | 100% | True for goals, including own goals and penalty shootout goals |
| is_touch | bool | 100% | True if the event counts as a touch of the ball |
| xg | float32 | 2% | Expected goals from the openplay xG model. Blank for own goals and shots from the team's own half |
| body_part | category | 7% | Head, Right Foot, Left Foot or Other Body Part, from the qualifiers |
| play_pattern | category | 2% | Situation: Penalty, Direct Freekick, From Corner, Throwin Set Piece, Set Piece, Fast Break or Regular Play |
| shot_zone | category | 2% | Area of the pitch the shot was taken from, from the qualifiers |
| shot_target | category | 2% | Where the shot went: Low Left, High Centre, Miss Right, Blocked, and so on |
| goal_mouth_y | float32 | 2% | Where the shot crossed the goal line, across the goal (0 to 100 scale, posts at about 45.2 and 54.8) |
| goal_mouth_z | float32 | 2% | Height where the shot crossed the goal line (bar at about 38) |
| blocked_x | float32 | 1% | x where the shot was blocked |
| blocked_y | float32 | 1% | y where the shot was blocked |
| related_event_id | int32 | 3% | team_event_id of a related event of the same team (for shots, the pass that set it up) |
| related_player_id | int32 | 3% | Player linked to the event (for example the passer for a shot) |

Plus 115 qualifier columns in this file (q_Zone, q_PassEndX, q_KeyPass, and so on). Flags are true/false, values are numbers or text. q_<name>_present columns mark qualifiers that sometimes appear without a value. See qualifier_dictionary.csv.

## coverage.csv

One row per competition-season: matches played, matches with event data, gaps, coverage percentage, matches with data issues.

165 rows. Columns: `comp`, `competition`, `season`, `in_v1_scope`, `matches_played`, `matches_with_events`, `gaps`, `coverage_pct`, `matches_with_data_issues`.

## known_gaps.csv

Played matches with no event data on the source (match id, competition, date, teams, score where known, reason).

1,606 rows. Columns: `match_id`, `comp`, `season`, `in_v1_scope`, `date`, `home_team`, `away_team`, `home_score`, `away_score`, `title`, `reason`.

## data_issues.csv

Matches with event data that has a known problem: score_differs_from_events, lineup_incomplete or few_events.

69 rows. Columns: `match_id`, `comp`, `season`, `date`, `home_team`, `away_team`, `in_v1_scope`, `issue`, `detail`.

## qualifier_dictionary.csv

Every q_ column in the events: source ID, how it is stored (flag, whole number, decimal, text), how often it appears.

115 rows. Columns: `qualifier`, `instances`, `with_value`, `used_without_value`, `seasons_present`, `stored_as`, `id`.
